# cloud37 (B1c) — align-on-EC2 → HealthOmics variant-only

Transferable, account-agnostic pipeline. Alignment + tumor merge run on **on-demand
EC2 via AWS Batch** (writing aligned BAMs directly to S3), then **Step Functions
auto-triggers a HealthOmics variant-only run** on the pre-aligned BAMs. Removes the
in-HealthOmics alignment cost and keeps HealthOmics outputs lean.

## Components
| File | Role |
|------|------|
| `cloud37-stack.yaml` | CloudFormation: Step Functions + AWS Batch (on-demand) + IAM + manifest Lambda. No account values baked in. |
| `Dockerfile` + `align_job.sh` + `merge_job.sh` | Align/merge container (minimap2 + samtools + aws-cli). |
| `write_manifest.py` | Reference for the manifest Lambda (also inlined in the stack). |
| `deploy.params.json` | Deploy-time parameter values — **the only file a new account edits**. |

## Transferring to a customer account (one command)

`bootstrap.sh` automates every prerequisite except supplying your own tumor/normal
BAMs. It mirrors the 8 `ontresearch/*` containers to your ECR (with the repository
policy HealthOmics needs to pull them), builds + pushes the align container, stages
the reference genome, uploads the workflow definition, deploys the prereqs stack (run
role + run group + HealthOmics workflow/version), then auto-generates
`deploy.params.json` and deploys the app stack.

```
python3 ../cloud-pipeline/build_workflow_zip.py      # -> cloud37-variant-workflow.zip (verified == cloud37-variant-rs3)
export SUBNETS=subnet-aaa,subnet-bbb,subnet-ccc      # your VPC subnets for Batch
export SECURITY_GROUP=sg-xxxx                         # your Batch security group
./bootstrap.sh <REGION> <BUCKET> cloud37-variant-workflow.zip   # or any local path / s3:// URI to the ZIP
```

### Image build: cloud-side by default (no local Docker)
`bootstrap.sh` builds the container image via **AWS CodeBuild** by default
(`BUILD_MODE=codebuild`) - it runs the mirror + build cloud-side on an amd64 CodeBuild
image, so the operator's machine needs **no Docker and can be any architecture**
(arm64 Macs included). To build on your own machine instead:
```
BUILD_MODE=local ./bootstrap.sh <REGION> <BUCKET> <WORKFLOW_ZIP>   # requires Docker w/ amd64
docker logout <ACCT>.dkr.ecr.<REGION>.amazonaws.com                # scrub cached ECR token
```

Requirements: awscli v2 + network access. `BUILD_MODE=codebuild` needs no Docker;
`BUILD_MODE=local` needs Docker with amd64 build support. Auth is ambient AWS credentials.

### What gets created
| Artifact | By | Contents |
|----------|----|----------|
| `cloud37-build` stack | `cloud37-build.yaml` | CodeBuild project (privileged, amd64) that mirrors the 8 containers + builds/pushes the align image. Only used in `BUILD_MODE=codebuild`. |
| `cloud37-prereqs` stack | `cloud37-prereqs.yaml` | HealthOmics run IAM role, run group (72h cap), variant-caller workflow + named version with container registry map. |
| `cloud37` stack | `cloud37-stack.yaml` | Step Functions + Batch (on-demand) + manifest Lambda. |
| `deploy.params.json` | generated by `bootstrap.sh` | wired from the prereqs stack outputs. |

### Manual path (if you prefer step-by-step)
1. **ONT containers** → for each of the 8 pinned images in `bootstrap.sh` (`IMAGES`): create `docker-hub/ontresearch/<name>`, pull/tag/push `ontresearch/<name>:<tag>`, then attach the HealthOmics pull policy: `aws ecr set-repository-policy --repository-name docker-hub/ontresearch/<name> --policy-text "$OMICS_REPO_POLICY"` (JSON in `bootstrap.sh`). Without it, HealthOmics runs fail to pull the image.
2. **Align container** → `aws ecr create-repository --repository-name cloud37-align`; `docker build --platform linux/amd64`; push; `docker logout`.
3. **Prereqs stack** → `aws cloudformation deploy --template-file cloud37-prereqs.yaml --stack-name cloud37-prereqs --capabilities CAPABILITY_IAM --parameter-overrides Bucket=<b> WorkflowDefinitionUri=<s3-zip>`.
4. **Edit `deploy.params.json`** from the prereqs stack outputs + your Subnets/SecurityGroup.
5. **App stack** → `aws cloudformation deploy --template-file cloud37-stack.yaml --stack-name cloud37 --capabilities CAPABILITY_IAM --parameter-overrides file://deploy.params.json`.

The only genuinely manual input is your own tumor/normal BAMs (step "Running one pair").

## Running one tumor-normal pair (per-run input)
Start a Step Functions execution with:
```json
{
  "sample_name": "COLO829",
  "bam_tumor":  "s3://<bucket>/inputs/.../tumor1.bam",
  "bam_tumor2": "s3://<bucket>/inputs/.../tumor2.bam",   // OMIT this key entirely for single-tumor
  "bam_normal": "s3://<bucket>/inputs/.../normal.bam",
  "ref":        "s3://<bucket>/inputs/references/GRCh38_no_alt_analysis_set.fna",
  "output_prefix": "s3://<bucket>/outputs/COLO829-<ts>/",
  "override_basecaller_cfg": "dna_r10.4.1_e8.2_400bps_sup@v4.2.0"
}
```
Inputs may be uBAM or aligned; each align job auto-detects (uBAM→minimap2, aligned→index).
For uBAMs, `align_job.sh` carries the source header (`@RG` read groups, `@PG` history)
into the aligned BAM, matching the header the HealthOmics alignment step writes.

## Output layout (per pair, one prefix)
```
<output_prefix>/
├── aligned_bams/tumor_aligned.bam(.bai), normal_aligned.bam(.bai)   # EC2 prep
├── manifest.json          # sources, aligned URIs, HealthOmics run id
└── <healthomics-run-id>/definition/output/   # VCFs, methylation, reports
```
`manifest.json` is the single source of truth for locating a pair's aligned BAMs + variant results.

## Credential hygiene
All auth is IAM-role based (Batch instance role, SFN role, HealthOmics run role) + ephemeral ECR token. No static credentials are stored in any artifact or the container image (`.dockerignore` blocks credential files from the build context).
